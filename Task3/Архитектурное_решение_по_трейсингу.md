# Архитектурное решение по трейсингу

## Проблема
Компания теряет заказы:
- Заказы зависают, сообщения теряются между сервисами
- Операторы не видят заказы из Shop API
- Яндекс.Метрика не видит бэкенд (RabbitMQ, MES, CRM)

## Решение: Трейсинг
**Эффект:**
- MTTR: 4-8ч → 15-30мин
- Потерянные заказы: ~5% → <0.1%
- Обработка жалоб: 2-3 дня → 15мин

## Критические точки отказа
1. **Shop API → RabbitMQ** - сообщение потеряно
2. **RabbitMQ → MES API** - consumer crash
3. **MES API → S3** - файл не найден
4. **MES API → RabbitMQ** - цена не отправлена
5. **CRM API → Shop DB** - статус не обновился

## Данные для трейсинга

**Обязательные атрибуты:** `trace.id`, `span.id`, `service.name`, `operation.name`, `duration`, `status.code`

**Бизнес-данные:** `order.id`, `customer.id`, `order.status`, `api.key` (для B2B)

**Технические:** `http.url`, `http.status_code`, `db.statement`, `rabbitmq.queue`, `s3.key`, `error.message`

**Пример trace:**
```
Trace: 7f8a9b2c... (3мин 45сек)
├─ [shop-api] POST /orders (120ms)
│  ├─ db.insert (45ms)
│  └─ rabbitmq.publish (10ms)
├─ [mes-api] calculate_price (185,000ms) ← BOTTLENECK
│  ├─ s3.download (1,200ms)
│  └─ analyze_polygons (175,000ms) ← 78% времени
└─ [crm-api] update_price (45ms)
```

## Технологический стек

**OpenTelemetry + Jaeger + Elasticsearch**

**Почему:**
- OpenTelemetry: vendor-neutral, поддержка Java/C#/JS, автоинструментация
- Jaeger: open-source, простой UI, low overhead
- Elasticsearch: 30 дней хранения traces

**Архитектура:**
```
[Shop/CRM/MES API] → [OTel Collector] → [Jaeger] → [Elasticsearch]
                                            ↓
                                      [Jaeger UI]
```

**Как работает:**
1. Shop API: создаёт `trace_id=abc123`, передаёт в RabbitMQ header
2. MES API: извлекает `trace_id`, продолжает trace
3. OTel Collector: отправляет spans в Jaeger (batching)
4. Jaeger UI: поиск по `order.id=ORD-12345`

**Deployment (Yandex Cloud):**
- OTel Collector: 1 EC2 (t3.medium)
- Jaeger: 1 EC2 (t3.medium)
- Elasticsearch: Managed (3 nodes, 8GB)
- **Стоимость:** ~$200-300/мес

## Компромиссы

**Не трейсим:**
- Frontend (Vue/React) - используем Яндекс.Метрику
- Внутренности БД - используем `pg_stat_statements`
- Legacy MES код - только entry points
- Third-party API - только наш HTTP client

**Sampling:**
- 10% обычных запросов
- 100% ошибок и медленных (>5 сек)
- 100% B2B API

**Retention:**
- 30 дней детальных traces
- 1 год агрегированных метрик

## Безопасность

**Угрозы:**
- Утечка бизнес-данных (цены, объёмы)
- Утечка PII (email, телефон) - GDPR
- Утечка API ключей B2B клиентов
- Exposure SQL injection

**Защита:**
1. **Доступ:** Jaeger UI через VPN + Yandex Cloud IAM (роли: Support/Engineer/Admin)
2. **Данные:** Маскировка API keys (`xyz1****`), parameterized SQL
3. **Сеть:** Internal network, TLS 1.3, security groups
4. **Rate limiting:** 100 req/min на пользователя
5. **GDPR:** Удаление traces по `customer.id`, retention 30 дней

## Автоматический мониторинг

**Архитектура:**
```
[Jaeger] → [Metrics Exporter] → [Prometheus] → [Alertmanager] → [Slack]
                                      ↓
                                 [Grafana]
```

**Метрики:**
1. **order_processing_duration** - время обработки (p50/p95/p99)
   - Алерт: p95 > 10мин
2. **order_stuck_count** - застрявшие заказы
   - Алерт: >10 заказов в SUBMITTED >1ч
3. **order_error_rate** - процент ошибок
   - Алерт: >1% ошибок за 5мин
4. **rabbitmq_message_latency** - задержка очереди
   - Алерт: p95 > 10сек

**Grafana дашборды:**
- Order Flow Overview (latency, застрявшие)
- Service Health (error rate, endpoint latency)
- Business Metrics (throughput, SLA compliance)

**Интеграция:** Grafana → Jaeger (deep link по `order.id`)
